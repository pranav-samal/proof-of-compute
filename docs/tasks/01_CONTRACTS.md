## 4. Step-by-Step Implementation Checklist

Each step has an **Expected result** you can verify before moving to the next.

- [ ] **A2.** Write stub contracts with correct function signatures and event declarations but empty/`revert("TODO")` bodies.

- [ ] **A3.** Run `scripts/deploy.ts` on `localhost` network; write `deployments/localhost.json`.  
  *Expected:* JSON file contains `address` and `abi` for all three contracts. **Commit and push this file.** Others are unblocked.

### Phase B — ProviderRegistry

- [ ] **B1.** Implement `registerProvider`, `depositStake`, `withdrawStake`, `freeStake`, `totalStake`.  
  *Expected:* Unit test: deposit 1 ETH, `freeStake` returns 1 ETH, withdraw 0.5 ETH, `freeStake` returns 0.5 ETH.

- [ ] **B2.** Implement `registerVerifier`, `withdrawBond`, `verifierBond`, `verifierCount`, `verifierAt`, `isEligibleVerifier`.  
  *Expected:* Unit test: register 5 verifiers, `verifierCount` = 5, `verifierAt(2)` returns correct address.

- [ ] **B3.** Implement `reputationBps` (initial value 10000), `recordOutcome`, reputation update logic.  
  Reputation update rule: `ACCEPTED` → no change or slight increase (owner-tunable); `REJECTED` → subtract 500 bps, min 0; `INCONCLUSIVE` → no change.  
  *Expected:* Unit test: provider starts at 10000, 2 REJECTED outcomes → reputation = 9000.

- [ ] **B4.** Implement `lockStake`, `unlockStake`, `slash`, `slashBond` with `onlyEscrow` modifier.  
  *Expected:* Calling these from non-escrow address reverts.

- [ ] **B5.** Write full `ProviderRegistry.test.ts` covering all branches.  
  *Expected:* `npx hardhat test test/ProviderRegistry.test.ts` passes, 0 failures.

### Phase C — VerificationPolicy

- [ ] **C1.** Implement `computeRisk` using the formula in SPEC.md §4.1 (integer bps arithmetic, no floats).  
  *Expected:* For payment = 1 ETH, stake = 10 ETH, reputationBps = 10000, Dh = 0, D class, assurance 1: compute expected riskBps manually and assert it.

- [ ] **C2.** Implement `derivePolicy` returning the `Policy` struct (SPEC.md §5.2).  
  *Expected:* For riskBps = 2000 → tier 0, verifierCount 1, quorum 1; riskBps = 6000 → tier 2, verifierCount 5, quorum 3.

- [ ] **C3.** Implement owner-only setters: `setWeights` (enforces sum == 10000), `setK`, `setChallengeWindow`, `setVerifierFeesBps`, `setSlashBps`, `setVerifierSlashBps`.  
  *Expected:* `setWeights` with sum ≠ 10000 reverts.

- [ ] **C4.** Write full `VerificationPolicy.test.ts`.  
  *Expected:* All passes.

### Phase D — JobEscrow (core)

- [ ] **D1.** Implement `registerJob` with payment locking.  
  *Expected:* Job ID increments; `getJob` returns correct fields; `msg.value` stored as `payment`.

- [ ] **D2.** Implement `assignProvider`: call `VerificationPolicy.derivePolicy`, lock collateral via `ProviderRegistry.lockStake`, record policy hash, emit `PolicyRecorded`.  
  *Expected:* Only requester can call; reverts if provider has insufficient free stake; policy hash on-chain matches `keccak256(abi.encode(policy))`.

- [ ] **D3.** Implement `commitResult`: check caller is provider, check deadline not passed, record `resultHash`, `checkpointRoot`, `resultCid`, `commitBlock`.  
  *Expected:* Reverts after deadline; second commit reverts.

- [ ] **D4.** Implement `selectVerifiers`: seed from `prevrandao` + `blockhash(commitBlock+1)`, Fisher-Yates over eligible verifiers excluding provider and requester, set `verifyDeadline`.  
  *Expected:* Reverts if called before `commitBlock+1`; correct number of verifiers selected per tier.

- [ ] **D5.** Implement `submitAttestation` with EIP-712 signature verification.  
  EIP-712 domain: `name="ProofOfCompute", version="1", chainId, verifyingContract=address(this)`.  
  Signed type: `Attestation(uint256 jobId, bytes32 policyHash, bytes32 resultHash, uint8 verdict, bytes32 evidenceHash)`.  
  *Expected:* Wrong signer reverts; non-selected verifier reverts; duplicate attestation reverts.

- [ ] **D6.** Implement `settle`: tally verdicts, determine outcome, distribute payments per SPEC §4.7 and §4.8, write `ReceiptRecord`, emit `JobSettled` and `ReceiptIssued`.  
  *Expected:* ACCEPTED: provider gets payment minus verifier fees; REJECTED: provider loses 50% collateral, requester refunded payment + 25% collateral, verifiers get 25% collateral split + 2% fee.

### Phase E — Timeout, Dispute, Views

- [ ] **E1.** Implement `claimTimeout` for provider commit timeout and verifier attest timeout.
- [ ] **E2.** Implement `resolveDispute` (arbitrator role).
- [ ] **E3.** Implement `getJob`, `getPolicy`, `getReceipt`, `getAttestation`, `selectedVerifiers` views.

## 7. Error Handling and Edge Cases

Every one of these must revert with a descriptive reason string:

- `registerJob`: `msg.value == 0` → `"JobEscrow: payment required"`
- `assignProvider`: caller ≠ requester → `"JobEscrow: not requester"`
- `assignProvider`: provider free stake < collateral → `"ProviderRegistry: insufficient free stake"`
- `assignProvider`: called twice → `"JobEscrow: already assigned"`
- `commitResult`: caller ≠ provider → `"JobEscrow: not provider"`
- `commitResult`: `block.timestamp > deadline` → `"JobEscrow: deadline passed"`
- `selectVerifiers`: `block.number <= commitBlock + 1` → `"JobEscrow: too early"`
- `selectVerifiers`: not enough eligible verifiers → `"JobEscrow: not enough verifiers"`
- `submitAttestation`: signer not in selected set → `"JobEscrow: not selected verifier"`
- `submitAttestation`: duplicate submission → `"JobEscrow: already attested"`
- `settle`: quorum not reached and verifyDeadline not passed → `"JobEscrow: cannot settle yet"`
- `withdrawStake`: amount > free stake → `"ProviderRegistry: exceeds free stake"`
- `setWeights`: sum ≠ 10000 → `"VerificationPolicy: weights must sum to 10000"`

## 8. Tests Required

File: `test/JobEscrow.test.ts`

```bash
# Run all tests
npx hardhat test

# Run with gas report
REPORT_GAS=true npx hardhat test

# Run with coverage
npx hardhat coverage
```

**Required test cases (each as an `it(...)` block):**

1. `registerJob` stores correct fields and emits `JobRegistered`
2. `assignProvider` locks collateral, records policy hash, emits `PolicyRecorded` and `ProviderAssigned`
3. `assignProvider` reverts when free stake < collateral
4. `commitResult` stores hash, emits `ResultCommitted`
5. `commitResult` reverts after deadline (claimTimeout path)
6. `selectVerifiers` returns correct count per tier, emits `VerifiersSelected`
7. `submitAttestation` accepts valid EIP-712 signature from selected verifier
8. `submitAttestation` reverts for non-selected verifier
9. `settle` — ACCEPTED: provider receives payment minus fee, verifiers receive fee
10. `settle` — REJECTED: provider loses 50% collateral, requester refunded, verifiers receive slash share
11. `settle` — INCONCLUSIVE: outcome held, arbitrator resolves
12. `claimTimeout` — provider did not commit before deadline
13. `claimTimeout` — verifiers did not attest before verifyDeadline
14. Full end-to-end honest run
15. Full end-to-end malicious provider (cheat mode): wrong hash detected, REJECTED outcome
